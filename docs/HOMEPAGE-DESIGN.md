# OT Hub 홈페이지 설계안

상태: 설계 시작
대상 버전: OThub2 0.2.0 이후 공개 홈페이지

## 1. 설계 목표

OT Hub를 콘텐츠 모음이 아니라 **필요한 일상 활동을 바로 시작하는 공개 작업치료 도구 공간**으로 보이게 한다.

첫 방문자의 첫 행동은 회원가입이나 설명 읽기가 아니라 다음 중 하나여야 한다.

- 일상 활동을 바로 연습한다.
- 작업치료 자료를 찾는다.
- 치료사 공간으로 이동한다.

로그인, 통계, 관리자 기능은 핵심 콘텐츠 탐색을 막지 않는 보조 레이어로 둔다.

## 2. 보존할 것과 새로 도입할 것

### 보존

- 현재 공개 콘텐츠와 훈련 HTML 경로
- `content.js` 기반의 단순한 콘텐츠 등록 구조
- 활동·영상·학회·기관이라는 세 가지 콘텐츠 유형
- 북마크, 최근 이용, 검색, 댓글·좋아요
- 모바일 하단 탐색과 키보드 접근성
- 로그인하지 않아도 콘텐츠를 시작할 수 있는 흐름
- 선택 동의 기반 통계와 관리자 권한 분리

### 새로 도입

- 홈페이지의 명확한 사용자 선택 구조
- 콘텐츠 카드의 대상, 목적, 필요 장비, 난이도 메타데이터
- 실제 훈련 화면을 보여주는 히어로 시그니처
- 공개 사용자와 치료사 사용자의 진입 경로 분리
- 기존 공개 홈페이지와 OThub2 사이의 기능 매핑
- 콘텐츠 목록과 실제 HTML 파일의 자동 일치 검사

## 3. Hallmark 설계 선택

**Hallmark · v2.0.0**

- **형태** · Workbench, draw `502fa3`
- **장르** · 전문적이지만 친근한 카탈로그형
- **테마** · Ink, 2/3. 흰 종이, 무채색 잉크, 하나의 청록 신호색
- **작업** · `try`: 방문자가 도구를 보고 바로 시작한다
- **내비게이션** · 상단 공지 띠와 한 줄짜리 공개 탐색 메뉴
- **히어로** · Counter. 왼쪽에 핵심 문장과 시작 버튼, 오른쪽에 실제 훈련 화면
- **푸터** · statement. OTHub의 역할과 운영 정보를 짧은 문장으로 마무리
- **시그니처** · 키오스크 훈련 화면을 실제 콘텐츠 카드가 아니라 “지금 시작할 수 있는 도구”로 보여준다
- **제외** · 숫자 통계, 가짜 후기, 로고 벽, 장식용 배지, 자동 회전 배너

Ink의 목록 중심 구조는 OThub2의 실제 콘텐츠 탐색과 잘 맞는다. 기존의 짙은 녹색 브랜드 색은 링크·포커스·활성 상태의 보조 색으로 유지하고, 화면 전체를 녹색으로 채우지는 않는다.

## 4. 제안 정보 구조

### 공개 상단 메뉴

- 도구
- 자료
- 치료사 공간
- OTHub 소개
- 검색
- 활동 시작하기

`관리자`는 공개 상단 메뉴에서 제외하고, 현재처럼 직접 경로와 인증으로 보호한다.

### 기존 경로 매핑

| 현재 경로 | 공개 화면 이름 | 역할 |
|---|---|---|
| `#home` | 홈 | 공개 홈페이지 |
| `#webapps` | 도구 | 바로 시작하는 활동 |
| `#videos` | 자료 | 영상 자료 |
| `#siteinfo` | 자료 | 학회·기관 링크 |
| `#bookmark` | 내 공간 | 이 기기의 저장 목록 |
| `#recent` | 내 공간 | 최근 이용 목록 |
| `#profile` | 치료사 공간 / 내 공간 | 로그인과 이용 설정 |
| `#updates` | 업데이트 | 공개 변경 기록 |
| `admin.html` | 비공개 | 관리자 통계 |

기존 해시 링크는 당장 깨뜨리지 않는다. 새 URL 체계는 운영 데이터와 SEO 계획을 확정한 뒤 별도 단계에서 바꾼다.

## 5. 홈페이지 구성

### 1) 상단 공지 띠

문구 예시:

> 작업치료사가 만들고, 함께 쓰는 일상 연습 도구

오른쪽에는 `활동 시작하기`와 `치료사 공간`을 둔다. 장식용 상태 점이나 버전 배지는 사용하지 않는다.

### 2) 히어로

헤드라인:

> 오늘 필요한 일상을, 먼저 연습하세요.

설명:

> 로그인 없이 작업치료 활동과 자료를 바로 시작할 수 있어요.

주요 행동:

- 활동 시작하기
- 치료사 공간 보기

오른쪽에는 `g6`, `g8` 등 실제 훈련 화면을 하나의 큰 화면 묶음으로 보여준다. 그림으로 만든 가짜 앱 창은 사용하지 않는다.

### 3) 시작점 선택

세 개의 큰 선택지를 둔다.

- **일상 활동** · 주문, 결제, 예매처럼 직접 연습하는 도구
- **작업치료 자료** · 영상과 참고 자료
- **치료사 공간** · 저장, 의견, 향후 평가 기록

각 선택지는 기능 이름보다 방문자가 얻는 행동을 먼저 말한다.

### 4) 바로 시작하는 도구

홈페이지에는 네 개의 무작위 카드가 아니라 다음 기준의 세 개를 보여준다.

- 카메라 없이 시작할 수 있는 활동 하나
- 일상생활 훈련 활동 하나
- 손 동작 또는 시선 기반 활동 하나

카드에는 다음 정보를 일정한 순서로 둔다.

1. 활동 이름
2. 연습 목적
3. 대상 또는 사용 맥락
4. 필요 장비
5. 시작 버튼

현재 데이터에 없는 값은 추측하지 않고 `운영 입력 필요` 상태로 남긴다.

### 5) 지역사회 활동 묶음

개별 게임을 나열하는 대신 하나의 생활 장면으로 묶는다.

- 편의점에서 장보기
- 카페에서 주문하기
- 기차표 예매하기

이 영역은 현재 공개 홈페이지의 I-ADL 묶음 방향을 이어받되, 실제 콘텐츠가 등록된 경우에만 노출한다. 코레일 콘텐츠처럼 파일은 있지만 카탈로그에 없는 항목은 먼저 등록 상태를 맞춘다.

### 6) 사용자별 다음 단계

좌우 두 영역으로 나눈다.

왼쪽:

> 누구나 먼저 도구를 경험해 보세요.

로그인 없이 시작할 수 있다는 사실과 카메라 필요 여부를 안내한다.

오른쪽:

> 치료사는 작업을 이어가세요.

로그인, 저장, 의견 기능을 안내하고 평가 기록은 실제 운영 범위가 확정된 뒤에만 노출한다.

### 7) 업데이트와 소개

업데이트는 카드 한 장으로 짧게 연결한다. 긴 로드맵은 업데이트 화면에 둔다. 제작자 소개는 신뢰를 보강하되, 히어로보다 앞에 두지 않는다.

### 8) 푸터

- OTHub의 한 문장 설명
- 도구, 자료, 치료사 공간, 소개
- 이용 데이터 안내
- 전체 개인정보처리방침과 문의 주소가 확정되면 함께 추가

## 6. 콘텐츠 데이터 보강안

현재 `id`, `type`, `title`, `img`, `url` 중심의 데이터에 다음 필드를 단계적으로 추가한다.

```js
{
  id: 'g6',
  type: 'game',
  title: '빽다방 키오스크 훈련',
  purpose: '일상생활 훈련',
  audience: [],
  skills: [],
  equipment: [],
  duration: null,
  difficulty: null,
  access: 'public'
}
```

`audience`, `skills`, `duration`, `difficulty`는 실제 운영자가 확인하기 전까지 비워 둔다. 임의의 연령, 효과, 성공률, 사용 시간은 표시하지 않는다.

## 7. 완료 기준

### 사용자 경험

- 첫 화면에서 서비스가 무엇인지 5초 안에 이해된다.
- 로그인 없이 활동을 시작할 수 있다.
- 일반 사용자와 치료사의 다음 행동이 구분된다.
- 도구를 목적과 필요 장비로 비교할 수 있다.
- 모바일에서 카드와 시작 버튼이 44px 이상의 터치 영역을 가진다.

### 콘텐츠

- `content.js`의 모든 로컬 URL이 실제 파일과 일치한다.
- 공개 홈페이지에서 숨겨진 기능이 있으면 소개 또는 치료사 공간에서 이유를 알 수 있다.
- 모든 카드에 실제 썸네일과 의미 있는 대체 텍스트가 있다.

### 운영

- 공개 도메인, Auth 리디렉션, 관리자 권한을 스테이징에서 확인한다.
- 통계는 기본 비활성 상태이며 동의 후에만 전송된다.
- 개인정보처리방침, 이용약관, 문의 창구를 출시 전에 확정한다.
- 실제 운영 데이터가 없는 숫자와 후기는 표시하지 않는다.

3. 새 홈페이지의 상단과 히어로 구현
4. 세 가지 시작점과 도구 목록 구현
5. 지역사회 활동 묶음과 사용자별 안내 구현
6. 기존 검색, 북마크, 최근 이용, 댓글·좋아요 회귀 테스트
7. 1280px·390px 화면 검토 후 운영 준비 체크

이 문서는 설계 초안이며 기존 코드의 동작을 변경하지 않는다.
